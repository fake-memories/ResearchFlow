# Day 5：有次数上限的最小工具 Agent

`app/tool_agent.py` 将 Day 4 固定的一次工具调用闭环放入循环。每轮都提供工具描述，模型可以根据已有结果继续提出搜索请求，也可以直接回答。工具描述、参数校验、搜索执行和响应检查复用 Day 4 的实现。

## 运行

在项目根目录、现有 `researchflow` 环境中运行：

```cmd
conda activate researchflow
python -m app.tool_agent
python -m app.tool_agent --request "请用一句话解释 Tool Calling，不需要检索论文。"
```

以上命令会请求真实模型；模型选择搜索时会访问 arXiv。仅查看命令帮助不会读取密钥或发起请求：

```cmd
python -m app.tool_agent --help
```

密钥仍从本地 `.env` 读取。默认配置为最多三次模型请求、30 秒请求超时、无 SDK 自动重试。

## 循环的执行顺序

1. 在循环外初始化 `messages`，保存系统要求和用户任务；初始化 `search_count = 0`。
2. 每轮调用一次 `client.chat.completions.create(...)`，传入整个历史和 `tools=TOOLS`。
3. 用 `read_message()` 检查响应；如果没有工具请求，读取有效答案并返回。
4. 如果已经是最后一次请求，却仍要求工具，报告任务尚未完成，不执行新的搜索。
5. 只允许本轮存在一条工具调用；多条调用整体拒绝。
6. 保存完整的 `assistant` 调用消息，显示调用 ID、工具名称和参数。
7. 如果此前已有成功搜索，等待三秒，再调用 `execute_tool_call()` 校验和执行工具。
8. 执行成功后增加搜索计数、追加 `tool` 结果消息、显示结果，进入下一轮。

普通回答判断必须放在上限检查之前，否则第三次恰好给出有效答案时也会被拦截。工具执行前必须检查上限，否则最后一轮搜索完成后，还需要一次超出预算的模型请求才能处理结果。

## 两种次数分别统计

`step` 表示当前第几次请求模型，`search_count` 表示已经成功完成几次搜索。它们不能相加当作模型请求次数；追加历史、打印日志和等待也不会请求模型。

| 路径 | 模型请求次数 | 成功搜索次数 | 结果 |
|---|---:|---:|---|
| 第一次直接回答 | 1 | 0 | 返回答案 |
| 搜索一次后回答 | 2 | 1 | 返回答案 |
| 搜索两次后回答 | 3 | 2 | 返回答案 |
| 三次响应都要求搜索 | 3 | 2 | 第三次搜索未执行，报告达到上限 |
| 第一次工具执行失败 | 1 | 0 | 报告失败，停止 |

最后一行的成功计数是零，但实际已经尝试过一次工具执行。`search_count += 1` 在执行函数之后，异常会中断流程，不会将失败计为成功，也不会自动重试。

`MAX_REQUESTS = 3` 时，最多有两次可以继续回传结果的搜索机会。将它改成 `2` 后，最多搜索一次。这是每轮只执行一条工具调用、且最后一轮禁止执行工具共同产生的限制。

## 消息历史如何累积

假设前两轮都成功搜索，发送每次请求时的历史如下：

| 请求轮次 | 消息数 | 角色顺序 |
|---|---:|---|
| 1 | 2 | `system → user` |
| 2 | 4 | `system → user → assistant → tool` |
| 3 | 6 | `system → user → assistant → tool → assistant → tool` |

`message.model_dump(exclude_none=True)` 保留调用名称、参数和 ID。`execute_tool_call()` 返回字典形式的工具结果，其 `tool_call_id` 对应具体调用 ID。仅保存模型正文或仅打印搜索结果，都不能构成完整回传。

把初始化移进循环会丢失前轮的调用和结果。在循环前额外请求一次模型，再进入最多三轮的循环，会使总请求次数最多达到四次；如果首个响应未处理就重新赋值，还会覆盖它。

## 搜索间隔与执行记录

这里采用简单的限速方式：第一次搜索前不等待，此后每次搜索前额外等待 `SEARCH_DELAY_SECONDS = 3` 秒。模型本身的响应耗时不从这三秒里扣除，所以实际间隔可能更长。等待发生在 Python 中，不会增加模型请求或搜索次数。

终端显示每轮模型请求编号、成功搜索次数、调用 ID、参数、搜索结果以及完成或上限状态。记录保留在本次终端输出中；消息历史保留在本次函数运行的内存中。

## 真实运行验证（2026-10-22）

以下结果依据本地运行截图整理，截图中两次运行均已返回 PowerShell 提示符。

### 一次搜索后回答

运行命令：

```cmd
python -m app.tool_agent
```

模型提出 `search_paper` 调用，参数为：

```json
{"query": "retrieval-augmented generation", "max_results": 2}
```

Python 执行搜索后返回两篇论文，第二次模型请求根据结果整理答案：

| 标题 | 首次提交年份 | 来源 |
|---|---:|---|
| Automated Literature Review Using NLP Techniques and LLM-Based Retrieval-Augmented Generation | 2024 | [arXiv:2411.18583v1](http://arxiv.org/abs/2411.18583v1) |
| Riddle Me This! Stealthy Membership Inference for Retrieval-Augmented Generation | 2025 | [arXiv:2502.00306v2](http://arxiv.org/abs/2502.00306v2) |

终端记录显示模型请求两次、成功搜索一次，最终回答的标题、年份与链接和工具返回一致。本次工具只返回检索元数据，没有读取论文全文；回答中对研究方向的概括仅能视作根据标题作出的推断。

### 无需搜索的直接回答

运行命令：

```cmd
python -m app.tool_agent --request "请用一句话解释 Tool Calling，不需要检索论文。"
```

模型第一次响应直接给出有效答案，程序正常结束。终端记录显示模型请求一次、成功搜索零次，没有工具执行记录。
