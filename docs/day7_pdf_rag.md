# Day 7：短文本 PDF 与页码来源

沿用 Day 6 的关键词检索、消息构造和单次生成，只增加 PDF 文本读取与页码定位。

## 数据流程

```text
PDF 文件
  → load_pdf：逐页提取文字，跳过空白页，返回片段列表
  → retrieve_ranked：关键词打分并取 Top-K
  → build_messages：问题、选中正文和完整来源标签
  → generate_answer：仅在启用 --ask 且有匹配时请求模型一次
```

当前样例每页较短，暂按一页一个片段处理，因此 `chunk_id` 均为 1。
`page` 是 PDF 页面顺序，从 1 开始；跳过空白页不会压缩后续页码。
来源文件名使用函数参数的 `file_path.name`。
仓库通过 `.gitattributes` 的 `*.pdf binary` 规则保留 PDF 字节，避免 Git 自动转换换行符。

```python
{"source": "demo.pdf", "page": 2, "chunk_id": 1, "text": "这一页的文字……"}
```

PDF 来源标签为 `[demo.pdf#p2-c1]`。Markdown 继续使用 `[文件名#片段编号]`。
`build_messages()` 根据片段是否包含 `page` 字段选择标签，并要求模型完整保留来源标签。

## 运行

在项目根目录、已激活的 `researchflow` 环境中运行。`pypdf` 已加入依赖清单。
查看逐页提取结果：

```powershell
python -m app.pdf_preview
```

查看选中的片段和准备交给模型的消息，模型请求为 0 次：

```powershell
python -m app.pdf_rag
```

以下前两条命令会把问题及选中的教学片段发送到项目已配置的 DeepSeek 服务。
分别核对第 1 页的数量规则、第 2 页的片段信息，以及无匹配时的零请求路径：

```powershell
python -m app.pdf_rag --ask
python -m app.pdf_rag --ask --question "每个片段需要保留哪些信息？" --keywords 来源 编号
python -m app.pdf_rag --ask --question "演示系统使用什么显卡？" --keywords 显卡
```

有匹配并启用 `--ask` 时，请求最多 1 次，超时 30 秒，自动重试为 0。
零匹配时在读取配置、创建客户端前返回 `资料中没有足够信息`。
问题和关键词仍是独立输入；有匹配也不保证材料足以回答问题。
